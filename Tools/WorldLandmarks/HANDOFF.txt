Persistent world landmarks - Claude handoff
Branch: codex/world-landmarks, based on 3c111af

WorldPlan now owns the landmark layout, grade, clearance and transport links.
Sectors project those saved buildings; mission seeds and crop origins cannot
reroll them. GenerationVersion is 3. The three implementation commits are:
  b10fa95  Plan permanent world landmarks and reserve graded footprints
  dc35814  Bind campaign sectors to validated permanent landmark layouts
  efa62f0  Render shared landmark volumes and expose immutable terrain hooks

Each tested world has four 450 x 350 m works near railway towns, two airfields
(880 x 30 m runways inside 1020 x 340 m footprints), and four 800 x 200 m rail
junctions with four connected sidings. Norvane's airfield uses its existing
Airbase site exactly. All features have a 64 m reserve and real road access.
Indexed reservations exclude farms, field parcels, forest and mission pads.
Height owns the graded platform and blended rim; local detail cannot regrade it.
Natural forest/marsh remain cover-based. DeepForest density work has not begun.

Hotspots reserve distinct feature windows before using generic geography.
If no usable feature remains, PlanAt returns a farmland sector instead of an
empty Industrial/Airfield/Rail identity. Generic windows leave landmark slots
free. A bounded wider base-pad search handles a wetland window whose central
island has insufficient space. Sub-two-metre road joins retain the gate link.

LandmarkMesh supplies the same slabs and building roots to local scenery and
LandmarkHlod. Local/distant slab clipping is complementary. FarScatter owns the
HLOD cache and releases it on origin/seed changes. There is no object per HLOD
building. Nine material submissions per landmark is the structural maximum;
the exported works/airfield/junction use 7/6/6 submissions and 330/196/344
triangles. These are mesh submissions, not measured HDRP render-pass counts.

Required terrain hooks for Claude / the terrain owner
  terrain-hooks.patch contains the exact hunks against this integration base.
  It is NOT applied here. Both patched files were compiled from Temp copies.
  Apply/adapt it after reconciling the other session's terrain changes.

  FarTerrain.BuildWorldTexture: after all road strokes, overlay each texel at
  its unwarped world centre using WorldPlan.FeatureSurfaceAt(wx,wz,out Color c).
  Store c directly (sRGB). CanopyGroundColour uses the same query first and
  returns c.linear. The patch includes the full loop and coordinate conversion.

  FarDetailData: capture WorldPlan.CaptureFeatureMap() on the main thread with
  the height/cover snapshot. Paint first queries features.SurfaceAt(x,z,out
  Color c), using unwarped world metres and returning c (sRGB). Surface uses:
    float detail = Mix(CoarseHeight(x,z), Height(x,z)+roughness,
                       Smooth(edge/128f));
    return Mix(Height(x,z), detail, features.DetailWeight(x,z));
  This height hook is necessary: ordinary tile roughness/coarse-edge blending
  must not cut through the platform. The snapshot is independent of later worlds.

  Cover audit: no new Cover value. Reserves use Pasture.
  - FarTerrain.BuildWorldTexture's Cover switch: default pasture remains valid;
    the feature-surface overlay follows roads so they cannot paint over runways.
  - FarTerrain.CanopyGroundColour's Cover if-chain: default pasture remains
    valid; the early feature query supplies the exact linear surface colour.
  - FarDetailData.Paint's Cover if-chain: default pasture remains valid; the
    early snapshot query supplies feature surfaces before cover displacement.
  - FarDetail.cs's stage++ and chunkStage++ switches are uploader states, not
    Cover. FarDetailChunks.cs/FarDetailRay.cs have no Cover switches to change.
